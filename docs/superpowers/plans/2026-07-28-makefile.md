# tabtoy Makefile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 GNU Makefile 复刻 `Make.sh` 的跨平台构建与打包，支持 amd64/arm64 交叉架构，并增加 `clean` 目标。

**Architecture:** 单一 `Makefile`。用 `define` 模板 + `$(foreach)`/`$(eval)` 生成 6 个 `build-<os>-<arch>` target，聚合 `build` 依赖它们全部；`clean` 清理构建产物但保留 `bin/` 下的测试数据。版本信息通过 `-ldflags -X` 注入 `build` 包，版本号取自 `git describe --tags --always`。

**Tech Stack:** GNU Make（目标版本 macOS 自带 3.81）、Go 1.26、纯 Go 交叉编译（无需 CGO）。

**Spec:** `docs/superpowers/specs/2026-07-28-makefile-design.md`

> **注：** 本计划为初始实现方案（`build` 聚合全部 6 组合、无 `help`）。实现后按用户要求演进：默认目标改为 `help`，`build` 改为仅构建当前宿主机平台，新增 `build_release` 全量构建，并增加 `help` 目标。最终设计以 spec 为准。

## 关键约束（实现前必读）

1. **Makefile recipe 行必须用 TAB 缩进，不能用空格。** 本计划代码块中的 recipe 缩进均为真实 Tab 字符，直接照搬即可。若误用空格会报 `*** missing separator`。
2. **`$(subst /,-,$(PLATFORMS))`** 做全替换，不要写成 `$(PLATFORMS:/=-)`（后者只替换词尾后缀，`darwin/arm64` 的 `/` 在中间，不生效，已实测）。
3. **`-ldflags '$(LDFLAGS)'` 用单引号**，不要用双引号。`date -R` 输出含空格，双引号包裹会让 shell 重新解析内层 `"` 导致按空格拆断；单引号让 shell 把内层 `"` 当字面量，go 链接器再自行解析（与 `Make.sh` 的 bash `"${VersionString}"` 等价）。
4. **不要设置 `CGO_ENABLED`。** tabtoy 是纯 Go（无 `import "C"`），跨架构编译已实测通过，保持与 `Make.sh` 一致。
5. **不要删除 `Make.sh`。** Makefile 与之并存。
6. 构建产物（`bin/`、`tabtoy`、`*.tar.gz`、`*.exe`）已在 `.gitignore` 中，`git status` 不会显示它们。

## Task 1: 创建 Makefile 主体（变量 + 构建模板 + build 目标）

**Files:**
- Create: `Makefile`

- [ ] **Step 1: 创建 Makefile，写入变量、构建模板与 build 目标**

创建仓库根目录的 `Makefile`，完整内容如下（recipe 行用 Tab 缩进）：

```makefile
# tabtoy 构建脚本（GNU Make）
# 交叉编译多平台二进制并打包，注入版本信息到 build 包

VERSION      := $(shell git describe --tags --always)
BINARY_NAME  := tabtoy
PACKAGE      := github.com/davyxu/tabtoy
BUILD_PKG    := github.com/davyxu/tabtoy/build
BIN_DIR      := bin
BUILD_FLAGS  := -v -p 4
PLATFORMS    := darwin/arm64 darwin/amd64 linux/amd64 linux/arm64 windows/amd64 windows/arm64

BUILD_TIME   := $(shell date -R)
GIT_COMMIT   := $(shell git rev-parse HEAD)
LDFLAGS      := -X "$(BUILD_PKG).BuildTime=$(BUILD_TIME)" \
                -X "$(BUILD_PKG).Version=$(VERSION)" \
                -X "$(BUILD_PKG).GitCommit=$(GIT_COMMIT)"

.DEFAULT_GOAL := build

# 单组合构建模板：$(1)=os  $(2)=arch
define build_platform
.PHONY: build-$(1)-$(2)
build-$(1)-$(2):
	@mkdir -p $(BIN_DIR)/$(1)-$(2)
	GOOS=$(1) GOARCH=$(2) go build $(BUILD_FLAGS) \
		-o $(BIN_DIR)/$(1)-$(2)/$(BINARY_NAME)$(if $(filter windows,$(1)),.exe,) \
		-ldflags '$(LDFLAGS)' $(PACKAGE)
	cd $(BIN_DIR)/$(1)-$(2) && \
		tar zcvf $(CURDIR)/$(BINARY_NAME)-$(VERSION)-$(1)-$(2).tar.gz \
			$(BINARY_NAME)$(if $(filter windows,$(1)),.exe,)
endef

# 把 "darwin/arm64" 拆成 os、arch 两参，生成 6 个 target
$(foreach p,$(PLATFORMS),\
	$(eval $(call build_platform,$(word 1,$(subst /, ,$p)),$(word 2,$(subst /, ,$p)))))

# 默认目标：构建全部 6 个组合（支持 make -j 并行）
.PHONY: build
build: $(addprefix build-,$(subst /,-,$(PLATFORMS)))
```

## Task 2: 增加 clean 目标

**Files:**
- Modify: `Makefile`（在文件末尾追加）

- [ ] **Step 1: 在 Makefile 末尾追加 clean 目标**

在 `Makefile` 末尾追加（recipe 行用 Tab 缩进）：

```makefile

# 清理构建产物，保留 bin/ 下的测试数据(.xlsx)与 .gitkeep
.PHONY: clean
clean:
	@find $(BIN_DIR) -mindepth 1 -maxdepth 1 -type d -exec $(RM) -r {} +
	$(RM) $(BIN_DIR)/$(BINARY_NAME) $(BIN_DIR)/$(BINARY_NAME).exe
	$(RM) $(BINARY_NAME)-*.tar.gz
```

- [ ] **Step 2: 制造构建产物**

Run: `make build-darwin-arm64 && ls -d bin/darwin-arm64 && ls tabtoy-*-darwin-arm64.tar.gz`

Expected: 确认 `bin/darwin-arm64` 目录与 tar 文件已生成。

- [ ] **Step 3: 执行 clean**

Run: `make clean`

Expected: 三条清理命令执行无报错（`find ... -exec rm -f -r`、`rm -f bin/tabtoy ...`、`rm -f tabtoy-*.tar.gz`）。

- [ ] **Step 4: 验证构建产物已删除**

Run: `ls bin/darwin-arm64 2>&1; ls tabtoy-*-darwin-arm64.tar.gz 2>&1`

Expected: 两行均为 `No such file or directory`（或 zsh 的 `no matches found`）。

- [ ] **Step 5: 验证 bin/ 下的测试数据与 .gitkeep 仍保留**

Run: `ls bin/*.xlsx 2>/dev/null | wc -l; ls bin/.gitkeep 2>/dev/null`

Expected: 第一行打印 `4`（`game_type_conf.xlsx`、`global_conf.xlsx`、`gm_command_conf.xlsx`、`greeting_message_conf.xlsx`），第二行打印 `bin/.gitkeep`。若 xlsx 数量为 0，说明 clean 误删了测试数据，回到 Step 1 检查 `find` 用的是 `-mindepth 1 -maxdepth 1 -type d`（只删子目录）。
